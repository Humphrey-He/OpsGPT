# GopherSentinel - 详细开发计划

> **项目周期**: 8 周 (全职) / 16 周 (兼职)
> **技术栈**: Go 1.21+ | Ollama/OpenAI | Qdrant | Redis | Docker
> **团队规模**: 1-2 人

---

## 第一阶段：基础 RAG 知识库构建 ⏱️ 第 1-2 周

### 🎯 阶段目标
> 构建一个能根据项目文档回答问题的 CLI 聊天工具

### 📋 任务清单

#### Week 1: 项目初始化与文档解析

| 序号 | 任务 | 交付物 | 预估工时 |
|-----|------|--------|---------|
| 1.1 | 初始化 Go 项目结构 (Clean Architecture) | `cmd/`, `internal/`, `pkg/`, `docs/` | 4h |
| 1.2 | 实现 Markdown/PDF 文档解析器 | `pkg/parser/markdown.go`, `pkg/parser/pdf.go` | 8h |
| 1.3 | 文本分块策略实现 (Chunking) | `pkg/parser/chunker.go` (支持滑动窗口) | 4h |
| 1.4 | 集成 Ollama API 客户端 | `pkg/llm/ollama.go` | 4h |
| 1.5 | Qdrant 向量数据库集成 | `pkg/vector/qdrant.go` | 6h |
| 1.6 | 基础 RAG 链路 (Embedding → 检索 → 生成) | `internal/rag/chain.go` | 8h |

#### Week 2: CLI 工具与对话功能

| 序号 | 任务 | 交付物 | 预估工时 |
|-----|------|--------|---------|
| 2.1 | CLI 框架选型与实现 (cobra/charm) | `cmd/cli/main.go` | 4h |
| 2.2 | 流式输出 (Streaming) 支持 | `pkg/llm/stream.go` | 4h |
| 2.3 | 对话历史管理 (上下文窗口) | `internal/memory/short_term.go` | 6h |
| 2.4 | 文档上传与索引命令 | `cmd/cli/ingest.go` | 4h |
| 2.5 | 基础问答对话命令 | `cmd/cli/ask.go` | 4h |
| 2.6 | 单元测试与集成测试 | `*_test.go` (覆盖率 > 60%) | 8h |

### 📁 目录结构

```
GopherSentinel/
├── cmd/
│   └── cli/
│       ├── main.go          # CLI 入口
│       ├── ingest.go        # 文档导入命令
│       └── ask.go           # 问答命令
├── internal/
│   ├── rag/
│   │   ├── chain.go         # RAG 链路
│   │   └── rerank.go        # Rerank 环节 (预留)
│   └── memory/
│       └── short_term.go    # 短期记忆
├── pkg/
│   ├── parser/
│   │   ├── markdown.go
│   │   ├── pdf.go
│   │   └── chunker.go
│   ├── vector/
│   │   └── qdrant.go
│   └── llm/
│       ├── ollama.go
│       └── stream.go
├── configs/
│   └── config.yaml
├── go.mod
└── README.md
```

### ✅ 阶段验收标准

- [ ] `go run main.go ingest ./docs` 能解析并索引 Markdown 文档
- [ ] `go run main.go ask "这个项目的架构是什么？"` 能返回流式回答
- [ ] 能正确处理文档分块和向量存储
- [ ] 单元测试覆盖率 > 60%
